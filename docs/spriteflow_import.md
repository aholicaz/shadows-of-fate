## ไฟล์และการเปิดดู

- PNG ที่เกมใช้อยู่: `Sprites/monsters/spriteflow/<monster_id>/`
- SpriteFrames: `data/sprites/monsters/<monster_id>_frames.tres`
- ค่าจัดวางภาพ: `data/monsters/<monster_id>.tres`
- เปิด `spriteflow_review.tscn` เลือก `monster_id` ที่ root ใน Inspector แล้วกด F6 ดูทุกท่า ทั้งซ้ายและขวา
- `war_wraith_review.tscn` เปิดดูนักรบเอซีร์ชุดใหม่โดยตรง
- ภาพจาก Godot และผลตรวจ: `output/spriteflow/runtime/<monster_id>/`
- รายการช่วงเฟรมและแหล่งไฟล์: `output/spriteflow/<monster_id>_manifest.json`
- ภาพก่อนเปลี่ยนของนักรบเอซีร์ถูกนำออกจากโฟลเดอร์ assets และเก็บใน `output/spriteflow/retired/` ซึ่งมี `.gdignore` ที่โฟลเดอร์แม่ จึงไม่ถูกนำเข้า Godot

## การจัดแอนิเมชัน

คัดช่วงท่าจากชุด 32 เฟรมตามภาพจริง ท่ายืน/เดินใช้ 8 FPS ท่าโดนตีใช้ 12 FPS ท่าตายใช้ 8 FPS การโจมตีใช้ระยะเวลาของเฟรมเพื่อให้จุดฟันแรกเริ่มที่ `attack_windup` เดิม และจบหลัง `attack_windup + attack_duration` เดิม (0.9 วินาทีสำหรับทั้งสี่ตัว) ไม่เพิ่มจำนวนครั้งที่ทำความเสียหายตามจำนวนฟันในภาพ

Run ใช้เฟรมเดียวกับ Walk; Skill ใช้ Attack เป็นภาพทดแทนตามระบบเดิม ท่า Die ของผู้พิทักษ์วานีร์หยุดที่เฟรมต้นฉบับ 27 เพราะตั้งแต่เฟรม 28 ตัวละครกลับมายืน

AtlasTexture ใช้ภาพเต็มโดยเพิ่มพื้นที่ว่างผ่าน margin ให้ทุกท่ามีผ้าใบ 1600×1400 และจุดยึด (800, 1100) วัดตำแหน่งคงที่จากสามเฟรมแรกของแต่ละชุด ไม่จัดกลางหรือย่อขยายพิกเซลทีละเฟรม ใช้ `fit_animation_scales` ชดเชยขนาดระหว่างชุดและพิกเซล alpha จางที่ SpriteFit นับ เพื่อให้ท่ายืนมีขนาดตาม `display_height` เดิม 180 / 250 / 320 / 210 ตามลำดับ ค่าพลัง กล่องชน ระยะโจมตี ของดรอป และข้อมูลความคืบหน้าไม่ได้เปลี่ยน

## ผลตรวจ

Godot 4.7.2 Steam / GL Compatibility / NVIDIA RTX 3050 Ti: ทดสอบผ่านทั้งสี่ตัว ตรวจผ้าใบทุกเฟรม จุดยึดทั้งซ้าย/ขวา สเกลคงที่ภายในแต่ละท่า การผูก Run/Walk จังหวะฟัน และการเล่นจริง 4.3 วินาทีต่อชุดพร้อมภาพจาก renderer ไม่พบข้อผิดพลาดใน assertions ของ sprites ชุดนี้

ตรวจ PNG ที่ใช้งานเทียบกับไฟล์ดาวน์โหลดด้วย SHA-256 และ alpha จริง ตรวจข้อมูลมอนสเตอร์เทียบกับสำเนาก่อนเปลี่ยนโดยยกเว้นเฉพาะค่าจัดภาพ

ข้อจำกัดจากต้นฉบับ: บางเฟรมมีดาบหรือเอฟเฟกต์ถึงขอบภาพ โดยเฉพาะท่าโจมตีนักรบเอซีร์เฟรม 4–6 ที่ปลายดาบเหนือหัวถูกตัดมาตั้งแต่ไฟล์ต้นฉบับ ดูรายการใน `output/spriteflow/validation.json` การเพิ่ม margin ไม่สามารถคืนส่วนที่ต้นฉบับขาดได้ และไม่ได้วาดเติม

การตรวจนี้ครอบคลุม sprites และการเล่นแอนิเมชัน ไม่ใช่การทดสอบการต่อสู้ทั้งเกม ระหว่างเปิดฉากยังมีข้อผิดพลาดของภาพ Jellopy, Drops Card และ King poring Card ที่ขาดในข้อมูลเดิม (ไฟล์ข้อมูลเหล่านี้ไม่ได้แก้ในงานนี้) รวมถึงข้อจำกัดการเขียน shader cache/log ของ sandbox รายละเอียดอยู่ในไฟล์ `*.stderr.log`
