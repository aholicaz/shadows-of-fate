# Forge Guardian — แก้ภาพเด้งระหว่างเฟรม

## อัปเดตจุดสัมผัสฝ่าเท้า

จุดยืนบนผ้าใบคงที่ไม่ตรงกับฝ่าเท้าจริง: Idle อยู่ y=439, Attack/Skill อยู่ y=434–435, Run อยู่ y=440–448 จึงยังเห็นเท้าลอย/จมแม้ขนาดลำตัวถูกต้องแล้ว

ใช้ `Fit Foot Region = (260,390,150,80)` วัดรองเท้าด้านที่ติดพื้น โดยไม่รวมค้อน/ลาวาทางซ้าย ใช้แถวที่มีอย่างน้อย 10 พิกเซล alpha > 0.4 แล้วชดเชยเฉพาะตำแหน่งแนวตั้งของภาพให้ฝ่าเท้าอยู่บนระดับชนเดิม ค่า scale และแกน X เดิมไม่เปลี่ยน วัดครั้งเดียวต่อท่าใน fit cache; ไม่สแกนภาพระหว่างเล่นแต่ละเฟรม

เปิดใน Idle, Run, Attack, Skill, Hit เท่านั้น ไม่บังคับท่าตายหรือมอนตัวอื่นให้ติดพื้น และไม่เปลี่ยนการกระโดดของมอน ผลวัดอยู่ `foot_audit_right.log`; ผลทดสอบ Godot อยู่ `foot_runtime.log` ตรวจฝ่าเท้าทุกเฟรมทั้งสองทิศรวมการเปลี่ยนท่า พร้อมทดสอบการตีและสกิล 5 ฮิตเดิม

## อัปเดตขนาดท่าเดิน

วัดแถวทึบของลำตัว/เท้าในช่วง x=220–379 (alpha > 0.1 อย่างน้อย 8 พิกเซลต่อแถว เพื่อไม่รวมค้อน): Run ค่ากลาง 384 พิกเซล, Attack ช่วงเตรียมเฟรม 0–5 ค่ากลาง 361 พิกเซล, Idle 363 พิกเซล ดังนั้นสเกลเดียวกันยังทำให้ตัวในชีทเดินใหญ่กว่า

ตั้ง `Fit Animation Scales` ใน `forge_guardian.tres`: `Run = 0.9401042` (361/384) ลดท่าเดินประมาณ 6% โดยใช้จุดยึดเท้าเดิมและตัวคูณคงที่ทุกเฟรม ท่าอื่นใช้ 1.0 ไม่ปรับขนาดตามการยกค้อน ขนาดลำตัวเดิน/เริ่มโจมตีหลังปรับต่างกันน้อยกว่า 1 พิกเซลในโลกเกม การย่อ/เอนตัวตามท่ายังคงเป็นภาพต้นฉบับ

ผลวัด: `size_audit.log`; ทดสอบ Godot ล่าสุด: `size_runtime.log`

## สาเหตุและการแก้

1. SpriteFit จัดกึ่งกลางจากขอบภาพรวมค้อน ทำให้ค่าแกน X ของ Skill สลับ -36 กับ -21 พิกเซล (ประมาณ 20.5 พิกเซลในโลกเกม) และเฟรมเดียวกันใน Attack/Skill ใช้ค่าจัดเท้าต่างกัน 8 พิกเซลต้นฉบับ
2. เปิด `Fit Fixed Anchor Enabled` เฉพาะ Forge Guardian ใน MonsterData ใช้จุดยืน `(280, 444)` บนผ้าใบ 512×512 ร่วมทุกท่า และใช้สเกลอ้างอิง Idle เดียวกัน ไม่จัดตัวใหม่ตามหัวค้อนหรือประกายไฟ
3. Skill เดิมตัดจากภาพต้นฉบับ 15 กลับ 12 ทันที เปลี่ยนเป็น 15 → 14 → 13 → 12 → 13 → 14 → 15 พร้อมช่วงเริ่มและคืนท่าครบ รวม 56 เฟรม / 20 FPS = 2.8 วินาที
4. Hit และ Die ตัดกริด 512×576 ผิดจากชีทจริง 512×512; Die ยังใช้จำนวนคอลัมน์ผิด ทำให้ติดภาพแถวถัดไปและวัดความสูงเป็น 572 พิกเซลจนระบบย่อบอส แก้กริดเป็น 8 คอลัมน์ และ Die ใช้ภาพ 0–15 จนล้มลงครบ (ไม่ต่อไปยังภาพยืนแถวท้าย)

เฟรมดาเมจ Skill ใหม่: **15, 21, 27, 33, 39** (นับจาก 0) ยังคง 5 ฮิต รัศมี/ความแรงเดิม ท่าธรรมดายังคงเฟรม 15 / 29 FPS

## ตรวจสอบ

Godot 4.7.2 GUI, OpenGL Compatibility: `runtime_verified.log` **0 failures**

- ตรวจจุดยืนและสเกลทุกเฟรมทั้ง 6 ท่า: Idle, Run, Attack, Skill, Hit, Die ทั้งซ้าย/ขวา รวม 340 เฟรมที่ตรวจ
- ทุกเฟรมใช้กริด 512×512 และทุกช่วงต่อของ Skill ใช้ภาพต้นฉบับที่ติดกัน

- ค่าเริ่มต้นบอสอื่นไม่เปิดระบบจุดยึดนี้
